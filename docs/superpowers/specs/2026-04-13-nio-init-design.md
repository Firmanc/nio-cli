# Design Spec: `nio init` - Shell Integration and DX Improvements

A top-level subcommand for the `nio` CLI to automate shell integration (the `cd` wrapper) and provide native shell auto-completions.

## 1. Problem Statement
The current `nio gtree switch` command relies on a manual shell function to perform the `cd` action. Additionally, users lack auto-completions for subcommands and branch names, making the tool feel less "native" to their workflow.

## 2. Core Features
- **Auto-Detection**: Automatically detect the user's shell (Zsh, Bash, Fish) using the `SHELL` environment variable.
- **Unified Initialization**: Provide a single `nio init [shell]` command that outputs a script for both the `cd` wrapper and auto-completions.
- **Native Completions**: Use `clap_complete` to generate shell-native completion logic for all `nio` subcommands.

## 3. Architecture & Technologies
- **Shell Detection**: `std::env::var("SHELL")` and string parsing to identify the shell type.
- **Completion Generation**: `clap_complete` crate to generate completion scripts for `Bash`, `Zsh`, and `Fish`.
- **Command Routing**: `clap` v4 for the top-level `init` command and `Shell` value enum.

## 4. Command Specification: `nio init [shell]`

### Logic:
1.  **Determine Shell**:
    - Use the provided `shell` argument if present.
    - If absent, read `$SHELL`. If it ends in `/zsh`, use `Zsh`; `/bash`, use `Bash`; `/fish`, use `Fish`.
    - Default to `Bash` if detection fails, and print a warning to `stderr`.
2.  **Generate Wrapper**:
    - Output a shell-specific function (e.g., `nio()` for Zsh/Bash) that intercepts `gtree switch`.
    - If the output of `command nio gtree switch` is a valid path (and not empty), the wrapper will `cd` into it.
3.  **Generate Completions**:
    - Use `clap_complete::generate` to produce the completion script for the target shell.
    - Append this to the wrapper output.
4.  **Stdout/Stderr**:
    - All script content MUST be printed to `stdout` (to be captured by `eval`).
    - Status or error messages MUST be printed to `stderr`.

### Example Output (Zsh):
```zsh
# Wrapper
nio() {
    if [[ "$1" == "gtree" && "$2" == "switch" ]]; then
        local target=$(command nio gtree switch "$@")
        if [[ -n "$target" ]]; then
            cd "$target"
        fi
    else
        command nio "$@"
    fi
}

# Completions (Generated by clap_complete)
# ... (Zsh-specific completion logic)
```

## 5. Implementation Steps
1.  Add `clap_complete` to `Cargo.toml`.
2.  Define the `Init` subcommand and `Shell` enum in `src/cli.rs`.
3.  Implement shell detection logic in a new `src/init/mod.rs` (or similar).
4.  Implement script generation logic for each supported shell.
5.  Update `src/main.rs` to route the `init` command.

## 6. Testing Strategy
- **Unit Tests**: Verify shell detection logic from various path strings.
- **Manual Verification**: Run `eval "$(cargo run -- init zsh)"` (or equivalent for other shells) and verify that `nio gtree switch` performs the `cd` and that tab-completions work for `gtree`.
